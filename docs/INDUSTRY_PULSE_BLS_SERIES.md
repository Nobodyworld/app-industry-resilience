**Status:** Reviewed implementation input for issue [#113](https://github.com/Nobodyworld/app-industry-resilience/issues/113)  
**Target:** `v0.3.0` Public Beta  
**Verification source:** BLS Producer Price Index current industry-series file, reviewed July 2026

## Purpose

This document fixes the initial Industry Pulse registry to official BLS PPI industry series before implementation. These mappings are contextual monthly signals only. They do not alter the annual output-to-cost ratio, Scenario Lab results, composite score, or indicator bands.

The BLS current-series format places the six-character NAICS industry code in positions 4–9 of a `PCU` series identifier and the industry/product code after it. The registry below uses the whole-industry series where the product code matches the six-digit industry code exactly.

## Registry rules

Implementation must enforce all of the following:

1. Series IDs are uppercase and match the official `PCU` industry-series structure.
2. The six-digit mapped NAICS code must equal the official BLS `industry_code` field.
3. The selected whole-industry series must use the same six-digit code for the product code; product-detail, primary-product, secondary-product, and miscellaneous-receipt series are not accepted as whole-industry mappings.
4. Series IDs and mapped NAICS codes are unique within this first registry.
5. Seasonal status is explicit; every initial mapping is not seasonally adjusted.
6. Registry labels may improve readability but must not replace or contradict the source title.
7. The BLS `base_date` field must be carried per series. Raw index levels must not be compared across unlike base dates as though they share a common scale.
8. Missing observations remain missing. Annual-average `M13` records must not be treated as a calendar month.
9. Mapped series remain contextual signals and must not feed the annual metric or composite calculations.

## Public API constraints

The application may use the existing BLS Public Data API v2 endpoint without embedding a registration key, while staying within the published unregistered limits. The implementation should batch this eight-series registry in one request and keep requested history within ten years for an unregistered refresh.

The offline snapshot is the default product path. Live refresh remains an explicit operator/application action behind the existing pipeline boundary and must not occur during API request handling, dashboard rendering, or hermetic tests.

## Offline snapshot requirements

The committed demonstration snapshot should:

- contain all eight registry series;
- contain a bounded recent monthly window sufficient for month-over-month and year-over-year calculation;
- exclude annual-average `M13` observations;
- preserve source series ID, NAICS mapping, observation month, value, units, seasonal status, base date, and release period;
- include a source/retrieval record and deterministic content hash;
- remain small enough for normal source control review;
- be generated by a documented script or fixture process rather than hand-edited values.

## Interpretation text

Every API/UI/export surface must retain this meaning:

> Producer Price Index observations show price movement for a verified mapped BLS industry series. They are contextual signals, not the dashboard’s annual output-to-cost ratio, and they do not establish profitability, resilience, insolvency risk, or causation.
