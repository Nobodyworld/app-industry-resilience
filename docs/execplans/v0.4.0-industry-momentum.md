## Purpose / Big Picture

The dashboard currently adds recent BLS producer-price context through Industry Pulse, while its
main annual analysis explains industry cost structure. After this work, a user can open a renamed
Industry Momentum tab and inspect official recent price, employment, industrial-production, and
capacity context for a selected industry, including exact versus broader mapping, latest value,
exact-calendar monthly and annual change, freshness, provenance, limitations, charts, tables, and
separate downloads. The user can also query canonical `/v1/context/momentum` API routes without any
provider request occurring during rendering or request handling.

These signals remain observations beside the annual analysis. They never change annual ratios,
rankings, Scenario Lab, health scores or bands, annual lineage, and they are not blended into a
score or used to claim profitability, resilience, insolvency, or causation.

## Context and Orientation

`src/core/industry_pulse.py` owns the released BLS PPI registry and typed signal contracts.
`src/application/industry_pulse_service.py` loads the committed PPI snapshot, validates its metadata,
computes exact-period changes and freshness, and performs no network requests. The canonical PPI API
lives in `src/interfaces/api/app.py` with response types in `src/interfaces/api/schemas.py`.
`src/interfaces/streamlit/industry_pulse.py` renders the current fifth tab, while root `app.py`
constructs services and declares the five first-class tabs. `src/application/industry_pulse_exports.py`
creates the existing separate PPI downloads.

`src/core/public_data.py` defines the no-auth source catalog and readiness stages.
`src/application/public_data_pipeline.py` supplies normalization, backfill, manifests, listeners,
and revision detection for public sources. Industry Momentum must extend that path instead of adding
an independent downloader.

A mapping relationship describes how an official provider's published industry scope relates to
the annual six-digit industry selected in the dashboard. `exact` is the same scope,
`broader_published` is an official broader grouping, and `manual_only` is browseable context without
a selected-industry match. A release fingerprint is a deterministic identity for the latest relevant
observation of every registered series; it must change if any registered series is revised.

### Milestone 2: create deterministic offline data and pipeline support

Add `src/scripts/generate_industry_momentum_ces_snapshot.py` and
`src/scripts/generate_industry_momentum_g17_snapshot.py`. Each generator uses only its official
provider, selects only registered series, normalizes first-of-month dates, excludes non-monthly
periods, rejects incomplete/unknown/duplicate/malformed/non-finite data, sorts deterministically,
writes a bounded January 2024 through latest-complete-month CSV plus typed metadata, and supports
validation-only operation. Outbound identity derives from the canonical project version. Tests use
committed fixtures and monkeypatched transports, never provider network.

Commit the four snapshot and metadata files under `data/`. Extend the existing public-data catalog
and pipeline so CES and G.17 truthfully advance only through evidenced stages. Multi-series release
fingerprints must include the latest relevant observation for every registered series, so revising a
non-final series changes the identity. Backfill, dry-run, manifest, no-change listener, duplicate and
revision tests prove the integration.

This milestone is accepted when both committed hashes match metadata, every registered series is
present, ordering and ranges are deterministic, and validation-only generator runs pass offline.

### Milestone 3: implement service, API, degradation, and exports

Overall and family states are `available`, `partial`, `unmapped`, `empty_range`, or `unavailable`.
Construction and request handling read committed files only.

`GET /v1/context/momentum/{industry_code}` with bounded `source_family`, `signal_type`, `series_id`,

routes, and a healthy peer family continue working.

provenance. JSON is the complete service envelope. XLSX uses `Price Signals`, `Employment Signals`,
`Production Signals`, `Capacity Signals`, and `Signal Metadata`, all within Excel's sheet-name limit.
Repeated export bytes are stable where promised and annual/signal provenance objects are unchanged.

This milestone is accepted by service, degradation, API/OpenAPI/compatibility, export parsing,
